## Storing User Data

So far your state lives only in memory — the moment the app closes, it's gone. Real apps store user data on the device. The main options:

| Storage | What it is | Best for |
|---|---|---|
| **AsyncStorage** | Simple key-value storage | Settings, small data, lists |
| **expo-secure-store** | Encrypted key-value storage | Passwords, tokens, secrets |
| **expo-sqlite** | Full database | Large, structured, queryable data |
| **expo-file-system** | Files on disk | Images, media, exports |

For this course you'll use **AsyncStorage** for most things and **SecureStore** for anything sensitive. [expo-sqlite](https://docs.expo.dev/versions/latest/sdk/sqlite/) is there when your data outgrows key-value storage.

## Offline-First Thinking

Mobile devices are offline a lot — on the bus, in a tunnel, in a basement. **Offline-first** means designing your app to work without a network connection, then syncing when connectivity returns.

Three habits:

1. **Cache what users need** — store fetched data locally so it's available offline
2. **Queue changes** — a note written offline is saved locally, then uploaded when online
3. **Tell the user the state** — show clear loading, offline, and error states

Offline-first isn't just a nice-to-have; users on unreliable networks are exactly the users who need your app most.

## Data Persistence Best Practices

A few rules keep persistence from becoming a mess:

1. **Persist deliberately** — save what matters, not every keystroke (debounce saves)
2. **Use one consistent key scheme** — e.g., `favorites`, `notes:v1` (a version suffix lets you migrate later)
3. **Handle corrupt data** — wrap reads in error handling; a crash shouldn't erase everything
4. **Keep secrets in SecureStore** — never AsyncStorage, never plain text
5. **Test the restart** — your app should look the same after closing and reopening

## Lab: Add Persistence to Your App

Take your Week 7 app (task tracker, notes, or favorites) and make it persistent:

1. Save the app's data to **AsyncStorage** whenever it changes
2. **Load it back on launch** — before or while the app starts rendering
3. Verify: add data, force-close the app, reopen — it's still there

**Deliverable:** your persistent data exercise, plus a note on what happens if the stored data is malformed (and how you handled it).
