**AsyncStorage** is a simple, persistent key-value store built for React Native — like `localStorage` on the web, but async. Perfect for settings, preferences, and small datasets like your favorites list.

## Install It

AsyncStorage is a community package. Install it with Expo:

```bash
npx expo install @react-native-async-storage/async-storage
```

[AsyncStorage: Getting started](https://react-native-async-storage.github.io/async-storage/docs/getting-started)

## Saving Data

Saving is a two-step process: **stringify** your data into a string, then **store** it under a key.

```jsx
import AsyncStorage from '@react-native-async-storage/async-storage';

async function saveFavorites(favorites) {
  try {
    await AsyncStorage.setItem('favorites', JSON.stringify(favorites));
  } catch (e) {
    console.error('Failed to save favorites', e);
  }
}
```

Note two things:

- `setItem(key, value)` takes **strings**, so arrays and objects go through `JSON.stringify`
- Wrap it in `try/catch` — storage can fail (full disk, permissions) and you should fail gracefully

## Loading Data

Loading reverses the process — **read** the string, then **parse** it back.

```jsx
async function loadFavorites() {
  try {
    const stored = await AsyncStorage.getItem('favorites');
    return stored != null ? JSON.parse(stored) : [];
  } catch (e) {
    console.error('Failed to load favorites', e);
    return [];
  }
}
```

Two things to handle:

- **First launch** — there's no value yet; return a sensible default (`[]`)
- **Corrupt data** — `JSON.parse` can throw; the `catch` returns a default rather than crashing the app

## Wiring It Into State

The classic pattern: **load on mount, save on change**.

```jsx
const [favorites, setFavorites] = useState([]);

// Load once when the component mounts
useEffect(() => {
  loadFavorites().then(setFavorites);
}, []);

// Save whenever favorites changes
useEffect(() => {
  saveFavorites(favorites);
}, [favorites]);
```

Now favorites survive app restarts: loaded from disk on launch, written to disk on every change.

## Secure Storage Concepts

AsyncStorage is **not encrypted** — it's fine for favorites and settings, wrong for secrets. For tokens, passwords, or anything sensitive, use **expo-secure-store**, which stores values in the platform's encrypted keychain/keystore.

```bash
npx expo install expo-secure-store
```

```jsx
import * as SecureStore from 'expo-secure-store';

await SecureStore.setItemAsync('auth-token', token);
const token = await SecureStore.getItemAsync('auth-token');
```

Same key-value idea, but hardware-backed encryption. **Rule of thumb:** data the user cares about → AsyncStorage; secrets that protect the user → SecureStore.

[Expo: SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/)
