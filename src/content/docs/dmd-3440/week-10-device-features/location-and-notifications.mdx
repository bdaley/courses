Two more native capabilities: **location** (where the user is) and **notifications** (telling the user something). Both come with permission and UX responsibilities.

## Location Services

Expo's **`expo-location`** gives you the device's position — and with it, the possibility of nearby content.

```bash
npx expo install expo-location
```

[Expo: expo-location](https://docs.expo.dev/versions/latest/sdk/location/)

A basic flow — request permission, get the position, do something with it:

```jsx
import * as Location from 'expo-location';

async function getLocation() {
  const { status } = await Location.requestForegroundPermissionsAsync();

  if (status !== 'granted') {
    setError('Location access is needed to show nearby routes.');
    return;
  }

  const pos = await Location.getCurrentPositionAsync({});
  console.log(pos.coords.latitude, pos.coords.longitude);
}
```

Same pattern as the camera: **request → check → handle denial → use**.

**Privacy note:** location is among the most sensitive data a phone holds. Only collect it for a real purpose in your app, and let users understand exactly why it's being collected.

[Expo: Location permissions](https://docs.expo.dev/versions/latest/sdk/location/#permissions)

## Notifications

Notifications can **remind, inform, and re-engage** users. They come in two flavors:

- **Local notifications** — scheduled and shown by the device itself ("Your bus leaves in 10 minutes")
- **Push notifications** — sent from your server through Expo's push service

For this course, **local notifications** are the right scope. They need no server and no accounts.

[Expo: Push notifications overview](https://docs.expo.dev/push-notifications/overview/)

The basics with Expo:

```bash
npx expo install expo-notifications
```

```jsx
import * as Notifications from 'expo-notifications';

// Request permission
const { status } = await Notifications.requestPermissionsAsync();

// Schedule a local notification
await Notifications.scheduleNotificationAsync({
  content: { title: 'Bus departure', body: 'Your bus leaves in 10 minutes.' },
  trigger: { seconds: 600 },
});
```

The permission dance is identical to location: ask, check the status, handle denial.

[Expo: expo-notifications](https://docs.expo.dev/versions/latest/sdk/notifications/)

## Designing for Notifications

Notifications should earn their interruptions. Good rules:

- **Relevant** — tied to something the user actually cares about
- **Timely** — arrives when it's useful, not at random
- **Respectful** — never spam; give users control to turn them off

Every notification your app sends should be a feature someone could point to in your Week 3 journey map. If you can't justify it, don't send it.
