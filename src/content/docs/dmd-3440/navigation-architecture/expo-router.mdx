Expo apps use **Expo Router**, which brings the web's *file-based routing* to mobile. The file system *is* the navigation: each file in your `app/` directory is a screen, and the folder structure defines how screens nest.

## Files Become Screens

In Expo Router, these files:

```
app/
  index.tsx          →  /
  routes.tsx         →  /routes
  settings.tsx       →  /settings
```

become three screens with these paths. To link between them, you use the `Link` component or `router`:

```jsx
import { Link } from 'expo-router';
import { Text } from 'react-native';

export default function Home() {
  return (
    <Link href="/routes">
      <Text>View Routes</Text>
    </Link>
  );
}
```

No navigation library setup, no manual stack definitions — just files and folders.

## Layouts — The "Chrome" of Your App

A **layout file** (`_layout.tsx`) wraps a group of screens and renders shared UI — most importantly, the navigation containers.

A tab layout for the bus app:

```jsx
import { Tabs } from 'expo-router';

export default function TabLayout() {
  return (
    <Tabs>
      <Tabs.Screen name="index" options={{ title: 'Home' }} />
      <Tabs.Screen name="routes" options={{ title: 'Routes' }} />
      <Tabs.Screen name="settings" options={{ title: 'Settings' }} />
    </Tabs>
  );
}
```

Put this `_layout.tsx` in `app/` and every screen under it gets a tab bar. A stack layout works the same way with `<Stack>` — and stacks nest inside tabs for that classic **tabs + stack** combination.

## Moving Between Screens with Data

To pass data along with navigation, use route parameters — like a URL query string:

```jsx
// Navigate with a parameter
<Link href="/routes/12">Route 12</Link>

// Read it in the destination screen
import { useLocalSearchParams } from 'expo-router';

const { id } = useLocalSearchParams();
```

This is how you go from a list (routes) to a detail screen (that route's schedule). Combined with stacks, it powers the drill-down flows you designed in your wireframes.
