## Mobile Sensors and Device Capabilities

A modern phone is full of hardware your app can use:

- **Camera** and photo library
- **GPS / location services**
- **Notifications** (push and local)
- Accelerometer, gyroscope, and compass
- Haptics (vibration feedback)
- Biometrics (Face ID / fingerprint)

Expo gives you all of these through the **Expo SDK** — one consistent API across iOS and Android.

[Expo SDK reference](https://docs.expo.dev/versions/latest/)

## Permissions — Ask Before You Use

Access to cameras, location, and notifications is **protected**. Your app must ask, and the user can say no (and change their mind later).

Three rules:

1. **Ask at the right moment** — when the user actually needs the feature, not at launch
2. **Explain why** — a short message before the system dialog, so users understand what they're granting
3. **Handle denial** — build a graceful fallback for when the user says no

Users are wary of apps that demand permissions for no clear reason. Respect the trust.

## Enhancing UX Through Native Features

Native features should serve your design, not decorate it:

- **Camera** — scan a receipt, snap a profile photo, identify a plant
- **Location** — "routes near me," weather at your coordinates
- **Notifications** — remind the user their bus leaves in 10 minutes
- **Haptics** — a tiny buzz confirming a successful save

Each feature is a *capability that supports a user goal* from your user journey map — not a checkbox to tick off.
