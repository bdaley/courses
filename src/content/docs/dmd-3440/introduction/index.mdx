Welcome to mobile app development! In this unit we'll step back and understand the **landscape** of mobile apps before writing any code: what the app ecosystems look like, the different ways teams build apps, and the tools and workflow you'll use all semester.

## The Mobile App Ecosystems

Mobile development is dominated by two platforms:

- **iOS** — Apple's operating system for iPhone and iPad. Apps are distributed exclusively through the **App Store**. Developers write native apps in **Swift**.
- **Android** — Google's operating system used by a huge range of manufacturers (Samsung, Google, Motorola, and more). Apps are distributed through the **Google Play Store** and other stores. Developers write native apps in **Kotlin** or **Java**.

Both platforms publish design guidance that shapes how apps look and behave:

- **Apple Human Interface Guidelines** — Apple's design principles for iOS apps
- **Material Design** — Google's design system for Android

Even though we'll build one app that runs on both, it's important to understand what's *native* to each platform — the gestures, navigation conventions, and visual language users already know.

## Native vs. Hybrid vs. Cross-Platform

There are three broad strategies for building a mobile app:

| Approach | What it means | Example tools |
|---|---|---|
| **Native** | Write a separate app for each platform, using that platform's language and tools | Swift + Xcode, Kotlin + Android Studio |
| **Hybrid** | Wrap a web app inside a native shell, so it runs in an embedded browser | Capacitor, Cordova |
| **Cross-platform** | Write once in a shared language that compiles to real native UI on each platform | **React Native**, Expo, Flutter |

We use the **cross-platform** approach. **React Native** lets you build an app with JavaScript and React, and it renders real native components on screen — not a web page. **Expo** is a framework and toolchain that sits on top of React Native and handles the messy native setup for you.

## Mobile Development Workflows

A typical mobile development workflow looks like this:

1. **Design** — research users, sketch ideas, and prototype in a tool like Figma
2. **Develop** — write code in your editor while a running app preview updates live
3. **Test** — run the app on a device or emulator, gather feedback
4. **Deploy** — submit the finished app to the app stores

This semester you'll repeat this loop throughout the course, and it all feeds into your **final project** — a complete app you design, build, test, and present.
