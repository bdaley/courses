CSS stands for **Cascading** Style Sheets. The "cascade" is the algorithm that decides which CSS rule wins when multiple rules target the same element.

Two main factors determine the winner: **specificity** and **source order**.

## Specificity

**Specificity** is a score the browser calculates for each selector. More specific selectors override less specific ones.

Here's the hierarchy from **least** to **most** specific:

| Selector type | Example | Specificity |
|---|---|---|
| Element selectors | `p`, `h1`, `div` | Low |
| Class selectors | `.highlight`, `.nav` | Medium |
| ID selectors | `#logo`, `#header` | High |

If two rules conflict, the one with higher specificity wins:

```css
/* Specificity: element (1 element) */
p {
  color: blue;
}

/* Specificity: class (higher than element) */
.highlight {
  color: red;  /* THIS wins over blue for elements with class="highlight" */
}

/* Specificity: ID (higher than class) */
#special {
  color: green;  /* THIS wins for the element with id="special" */
}
```

## Source Order

When two selectors have the **same specificity**, the one that comes **last** in the CSS wins:

```css
/* Both are class selectors — same specificity */
.intro {
  color: blue;
}

.intro {
  color: red;  /* This wins because it comes last */
}
```

This is why the order of your CSS rules matters.

## The Full Picture: Cascade + Specificity

The browser follows this process for every element:

1. **Collect** all CSS rules that apply to the element
2. **Sort** by specificity (more specific = higher priority)
3. **Sort** by source order (last rule wins among ties)

```css
/* Rule 1: element selector — specificity: 0,0,1 */
p {
  color: gray;
}

/* Rule 2: class selector — specificity: 0,1,0 */
.warning {
  color: orange;
}

/* Rule 3: ID selector — specificity: 1,0,0 */
#critical {
  color: red;
}

/* Rule 4: element + class — specificity: 0,1,1 */
p.warning {
  color: darkorange;  /* More specific than just .warning alone */
}
```

## Inline Styles

Inline CSS (the `style` attribute on an HTML element) has the **highest specificity** — it beats any selector in your stylesheet:

```html
<p style="color: red;">This will be red, no matter what your CSS says.</p>
```

This is why inline CSS is dangerous — it's hard to override later. Use it sparingly, if at all.

## The `!important` Exception

The `!important` flag forces a rule to the highest priority, beating even inline styles:

```css
p {
  color: red !important;
}
```

```html
<p style="color: blue;">This text will be RED because of !important</p>
```

**Avoid `!important`** in almost all cases. It breaks the normal cascade and makes your CSS harder to debug. If you're using `!important` frequently, it's usually a sign that your specificity structure needs work.
